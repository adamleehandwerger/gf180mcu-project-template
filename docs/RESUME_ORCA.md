# Resuming the GF180MCU Harden After Scratch Expiry

The ORCA **scratch** workspace `/scratch/funphin-openlane_svm/` expires **2026-08-29**. This does
**not** mean starting over — the design is fully in git and the sign-off outputs are backed up.
This page is the recipe to rebuild the flow afterward (or on any fresh machine).

Because the SIF + PDK are stashed in **home**, resume needs **zero downloads**.

## Pinned versions (for a from-nothing rebuild, if the stashes are ever lost)

- **LibreLane SIF:** `apptainer pull docker://ghcr.io/librelane/librelane:3.1.0.dev2-x86_64`
- **PDK (ciel):** `ciel enable f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7 --pdk-family gf180mcuD --include-libraries all`
- **SCL / pad:** `gf180mcu_fd_sc_mcu7t5v0` / `gf180mcu_fd_io` · **slot** `0p5x1`
- nix is **not** usable on ORCA and `make` is not in the SIF — run `ciel` + `librelane` directly.

## Resume steps (after 2026-08-29)

```bash
# 1. Pick a new working dir (new scratch allocation, or /home if it fits ~50GB of runs)
NEW=/scratch/funphin-openlane_svm2          # or wherever
mkdir -p $NEW && cd $NEW

# 2. Reconstitute the project from git (the design source of truth)
git clone -b svm-integration https://github.com/adamleehandwerger/gf180mcu-project-template.git gf180mcu-svm

# 3. Restore the stashed build env (no downloads). If the stash is gone, use the
#    pinned pull/enable commands above instead.
cp $HOME/gf180_env/librelane_dev.sif $NEW/librelane_dev.sif
cp -r $HOME/gf180_env/gf180mcu       $NEW/gf180mcu-svm/gf180mcu

# 4. Point the harden script at the new paths, then submit
#    (edit ~/gf180_harden.sh: SCRATCH=$NEW ; SIF/PROJ follow from it)
sbatch ~/gf180_harden.sh                     # long partition; ~40 min; -> PROJ/final
```

The harden reproduces the signed-off result (job 127101): DRC/LVS/antenna 0, hold +0.26 ns,
setup +14 ns typical / −5.07 ns worst slow corner, GDS in `.../final/gds/chip_top.gds`.
